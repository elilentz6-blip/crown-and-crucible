# Crown & Crucible: visuals and rendering (owner: Claude)

The playable overworld is drawn by `obj_vis_renderer` (placed in `Room1`). It reads the gameplay
state from `obj_game` and `obj_player` every frame and never changes it. If the renderer instance
is removed, `obj_game`'s legacy Draw / Draw GUI code takes over again (each of those events exits
early only when `obj_vis_renderer` exists).

## Scale and style
- 1 art pixel = 1 world pixel, on a 32px tile grid. The camera defaults to 2x (the mouse wheel or
  the - / = keys switch between 1x, 2x and 3x), so pixels stay square and crisp.
- Light comes from the top-left. Outlines are dark and hue-shifted, never pure black.
- `option_mac_interpolate_pixels` is off.

| Renderer: terrain, scene, camera, particles, dialogue | `scripts/scr_vis_world` |
| Draw passes: world, lighting, glow, GUI labels | `scripts/scr_vis_draw` |
| Weather: state machine, rain, puddles, fog, lightning | `scripts/scr_vis_weather` + `art_src/world/weather.py` |

`build_all.py` regenerates every `spr_world_*`, `spr_bld_*`, `spr_veg_*`, `spr_prop_*`,
`spr_portal_*`, `spr_fx_*`, `spr_char_*`, `spr_portrait_*` and `spr_ui_*` sprite, then registers
them in the .yyp:

`<venv>/bin/python art_src/world/build_all.py` (needs Pillow and numpy)

## Rendering pipeline (per frame)
1. Animated water tiles (`spr_world_water`) under the terrain.
2. Terrain chunks: 1024px surfaces baked lazily from a dual-grid (corner) terrain map. Each tile
   blends up to 9 terrain types using 14 transition masks, and gets scattered ground decorations.
3. Ground-level art: bridges and the portal dais.
4. The y-sorted scene. Static sprites (buildings, props, vegetation) sit in 64px buckets and are
   merged with live actors (hero, villagers, companions, foes, sheep, chests) sorted by feet y.
5. Particles, then drifting cloud shadows.
6. Lighting: a view-sized surface is cleared to the ambient time-of-day colour, coloured lights
   are added to it, and the result is multiplied over the world.
7. Additive glow: lit windows (frame 1 of each `spr_bld_*`), lamps, the portal's runes and halo,
   and fire.
8. GUI: vignette, name plates, the interaction prompt (same ranges and priority as obj_game),
   floating text, the HUD, the location title and the typewriter dialogue with portraits.

## Weather
`scr_vis_weather` blends five states: Clear, Overcast, Rain, Storm, Fog. Each sets targets for
`cover` (cools and darkens the ambient, lights windows/lamps by day, hides cloud shadows),
`rain` (13 px streaks slanted by the wind, splashes, ripples on water tiles and puddles; puddles on
pure dirt/cobble/plaza tiles fill as the ground gets wet and dry over ~45 s), `fog` (a wash plus
drifting `spr_fx_fog` banks tinted by the ambient light, drawn after lighting so lamp glows punch
through) and `storm` (lightning bolts stepped one art pixel at a time, a double sky flash and a
2.5 px camera shake). The weather drifts by itself every 1-2.5 minutes (weighted: clear -> overcast
-> rain -> storm, fog now and then); **R** cycles it in the overworld and holds the pick for 4
minutes. A toast names each change. Nothing is drawn indoors. Weather never touches gameplay state.
Sprites: `spr_fx_rain` (streaks 0-3, splash 4-7, ripple 8-11, bolt pixel 12), `spr_fx_puddle`,
`spr_fx_fog`, generated by `art_src/world/weather.py` (also callable standalone).

## Game feel and the realm map (Phase 5)
`scr_vis_feel` watches gameplay state and presents it: transitions on mode changes (drawn in the renderer's
Draw GUI End, so above battle and menus), toasts (quests, level-ups, save/load, war news), the HUD's rolling
gold, HP trail and XP bar, chest glints, footstep dust. `scr_vis_map` is the M-key map, game mode `MAP`,
which gameplay step code ignores. Full audit: `docs/PHASE5_VISUAL_AUDIT.md`.

## Dialogue box
`vis_dialogue_step` presents `obj_game.overworld_dialogue_text`. Z/Space/Enter: first press
finishes the typing, second press closes it; a closed line replays on the next press. Walking more
than 150 px away closes it. obj_game's filler line for "interact with nothing" ("You look across
the wide realm...") is never shown, because it made the box reopen whenever the player pressed
Space to close it. Text uses `body_bold` in `UI_COL_DIALOGUE_INK` on a flattened parchment backing.

## Interfaces for other agents
- **New NPC visuals (Gemini):** add a spec in `art_src/characters/defs/`, run the character
  generator and then `build_all.py`. Point any NPC struct at it with `visual: "<key>"`.
  Otherwise `vis_char_key()` maps the existing ids, roles and names.
- **New dimension / town:** register a theme with `vis_theme_register(name, {...})` (terrain,
  water and deco sprites, ambient light per time of day, vegetation and deco rules). Then write
  a layout function like `vis_layout_stonecross()` (terrain ops, buildings, props, solids,
  keep-outs, portal).
- **Collision:** art-placed obstacles (trees, rocks, extra houses, fences, the portal and the
  fountain rim) are queried through `vis_solid_at(x, y)`, which `check_overworld_solid()` calls
  first. The second river bridge (x 2010-2110) is a gap in the river band, so the Barrows are
  reachable.
- **Dialogue:** the renderer presents `obj_game.overworld_dialogue_text` whenever it changes. The
  speaker is the nearest villager or companion (with portrait) or the landmark in range.

## QA
Run the dev screenshot tour with `CC_VIS_TOUR=1` in the runner's environment. It visits 29 stops
(times of day, interiors, door fades, dialogue, and seven weather stops; storm stops force a strike), saves `tour_*.png` into the runner's save folder and quits. Screenshots
from the build are in `art_src/screenshots/` (`weather_*.png` for weather).
`CC_VIS_SNAP=1` instead leaves the hero untouched, presses Space at 3 s and 4 s, saves `snap_0..3.png`
(1, 3.2, 5 and 8 s) and quits: a regression check that the welcome box closes and stays closed.
Launch the runner with an absolute `-game` path; a relative one makes it look in the save folder.
