# Crown & Crucible (GameMaker project "BLANK GAME")

- Project root: ~/GameMakerProjects/BLANK GAME/ (project file: `BLANK GAME.yyp`). GameMaker 2024.14.4.222 on macOS (Apple Silicon).
- Code: `objects/` (each object's events are .gml files next to its .yy), `scripts/` (e.g. `scr_art_engine`), `rooms/` (`Room1`).

- Always update both canonical project documents whenever changing systems, narrative, quests, or features: `CROWN_AND_CRUCIBLE_MASTER_DOSSIER.md` (Master Project Dossier) and `docs/STORY_BIBLE.md` (Story Bible & Writer's Room).

## Running a build without crashing the runner
- GameMaker is signed in; use the user folder `~/Library/Application Support/GameMakerStudio2/elilentz6_5139243` for Igor `--uf`.
- Never launch `Mac_Runner` on a `game.ios` unless `options.ini` (and `splash.png`) from the same Igor build sit in the same folder. Without `options.ini` the runner segfaults in `IniFile::GetSection` and macOS pops a crash dialog.
- Use `~/GameMakerProjects/_build/` for test runs and kill the runner (`pkill -f Mac_Runner`) when done.

### More runner and project-file rules (added Oct 29, 3 PM ET)
- Always launch the runner with `-game ~/GameMakerProjects/_build/game.ios`, with `options.ini` and `splash.png` next to it. Never launch the runner bare, never open `~/gamemakerstudio2/GM_MAC/BLANK_GAME/YoYo Runner.app` directly, and never launch with a missing or unbuilt `game.ios`. ## Agent coordination rules (added Oct 30, 1:35 PM ET)
Four agents work on this repo: Claude, Gemini (Antigravity), Codex/ChatGPT and Grok Bot. They coordinate through `docs/AGENT_BOARD.md` and its helper, `tools/board.sh`. Always use the live board in `~/GameMakerProjects/BLANK GAME/docs/`, even when you are working in a worktree or clone. The runner and isDnD rules above still apply.
1. **Read the board first.** Read `docs/AGENT_BOARD.md` at the start of every task and again before you edit anything. Run `tools/board.sh inbox <YourName>` and act on any messages addressed to you or to All.
2. **Claim before you edit.** Run `tools/board.sh claim <YourName> <path> "<why>"` before you edit a file or folder. When your work is merged or abandoned, run `tools/board.sh release <YourName> <path>`. Never edit a path that another agent has claimed. If you need it, post a message to that agent. `BLANK GAME.yyp` is shared: claim it only while you register resources, then release it straight away.
3. **Never destroy another agent's work.** Do not run `git checkout -- <file>`, `git restore`, `git reset --hard`, `git clean`, `git stash` or `git push --force` on any file you did not change yourself. If another agent's work breaks a build or test, leave it in place and post a message to that agent (`tools/board.sh post <You> <Them> "..."`), with the failing test and its error.
4. **Work on your own branch and worktree.** Before you start, update from main (`git fetch && git rebase origin/main`, or `git pull --rebase`). Then work on a branch named `agent/<yourname>-<task>`, preferably in your own worktree (`git worktree add ~/GameMakerProjects/_wt/<yourname>-<task> -b agent/<yourname>-<task> origin/main`), so that switching branches never touches another agent's files. Commit often.
5. **Merge to main only when everything passes.** Before you merge, all of these must pass: the Igor build with 0 compile errors; `tests/run_all.cjs`, `challenger_stress.cjs`, `challenger_m2_stress.cjs`, `challenger_m2_adversarial.test.cjs` and `chronicles_greenmere.test.cjs`; and a 15-second `-game` smoke run in `~/GameMakerProjects/_build/` (with `options.ini` and `splash.png` next to `game.ios`). Then push normally, never with force, and record the commit hash with `tools/board.sh done <You> "<summary> <hash>"`.
6. **Keep your status current.** Run `tools/board.sh status <YourName> <working|blocked|review|done|idle> "<task>"` when you start, finish, get blocked or need something from another agent. When you need something, also post a message to that agent.
7. **Ask Eli about canon and design.** Don't decide lore, canon, title or art-direction questions yourself. Post them to `Eli` on the board, and keep working on something else meanwhile.
